### Important remaining concerns and explicit blockers

The PR-A test keypair is generated by CI and intentionally **not** a
real-world trust anchor. Before any real-world operation, PR-B must pin and
independently review the true public key and approval channel. A signed
host receipt cannot replace actual inspection of the named host and the
actual runtime mounted secret/egress separation. An operator must review
GPL/AGPL network-use and publication requirements independently.

The test-only fake gateway uses a private local-session adapter. The
production `LiveGateway` never takes a caller-controlled URL. Tests that
exercise local HTTP are not proof of real CA/DNS/TLS behavior, so TLS host,
proxy, redirect, and 401/403 negatives are separately required and any
untested area is a **blocker**.

A receipt asserting no descendants is not itself proof; the Docker
supervisor and independent process inspection must cover the actual PID
namespace. Real first-game power loss and crashed network calls are
recovery-specific host hazards even when offline synthetic crash tests
pass. Never resend an uncertain move: obtain authoritative full-history
confirmation or suspend.

A blank heartbeat line is not stream EOF. A long-running account/event
stream and game stream must not monopolize the nonstream mutex. The
pinned bot may return `offeringDraw=false` on move POST: the gateway
permits precisely that value and rejects `true`.

**Claim cap:** only an independently replayed fake-server game is eligible
for `DRY_RUN_PASS`; successful PR code is not authorization, rating
evidence, a live-host qualification or a legal conclusion.

### Independent move authority and durable stop
The gateway must inspect the bridge SQLite journal via a read-only mount;
untrusted `X-Allfather-Ply` and `X-Allfather-Epoch` headers cannot substitute
for a real `SUBMITTING` intent. An adverse move attempt with no matching
journal row, wrong epoch or wrong player turn must produce **zero** external
move requests. The cross-namespace stop-control volume contains a durable
stop marker only; it contains no Lichess token. A stop during a game is a
containment outcome, never proof of successful game completion.

### API compatibility and minimal-side-effect refinement
The official token-test schema encodes scopes as comma-separated text. The
gateway checks the exact `bot:play` member and rejects elapsed or malformed
expiry timestamps. Unknown game status values suspend the game before chess
work. An unapproved challenge is filtered rather than forwarded to the pinned
bridge; PR-A deliberately disables even generic account-side challenge declines
because there is no separately admitted decline-target allowlist.

### Exact live profile bytes inside disposable bridge

The pinned upstream Git tree and original OFFLINE-4B overlay remain unchanged.
After verifying upstream and applying its source-locked patch, the separate
live staging code checks `HEAD:deploy/lichess/guarded_transport.py` and
`HEAD:deploy/lichess/live_gateway_policy.py` and places those exact bytes
in the temporary bridge. Its overlay manifest retains patched upstream OIDs,
records the live module digests, and refuses mismatched prior guard bytes.
This avoids accidentally executing the inherited offline-only transport
adapter from an older packaged image during a later operator-approved canary.

### Repair review checks

- The gateway bridge journal check reads epoch, game and prepared intent in one
  read-only WAL transaction, not across potentially different SQLite snapshots.
- The source/host gate recomputes the canonical observation digest from the
  entire host report and refuses modified nested resource or network facts.
- CI test orchestration observes both actual Docker container image IDs and
  their exact read-only source mounts before signing synthetic fixture input.
- An authoritative terminal event can precede the other namespace's fsynced
  final witness. The bridge may wait within its existing bounded deadline but
  never emit a terminal SUCCESS without that witness.
- The synthetic producer retains only fixed-stage negative receipts on failure;
  neither producer success nor CI step success by itself grants live authority.

### Dedicated executable staging surface (PR-A repair, synthetic only)

The copied UCI launcher must remain executable for the pinned upstream
configuration validator and actual engine process. Granting `exec` to
general `/tmp` would broaden an unrelated scratch surface. Instead,
the canary bridge admits only an exact separate 1-GiB `tmpfs` mount at
`/run/allfather-canary-stage`, with UID/GID 10001, mode 0700,
`exec,nosuid,nodev`. The general `/tmp` mount remains `noexec`.
There are no secrets or durable state under the executable mount.

Risk introduced: temporary writable-and-executable memory-backed storage.
Mitigations: an exact allowlisted mountpoint, private unprivileged ownership,
no host bind, no device access, no SUID, bounded size, source-sealed copied
upstream and engine bytes, fixed disposable workspace, and normal child
process controls. The runtime reads actual `/proc/self/mountinfo` and
refuses missing/ambiguous, `noexec`, incorrect owner/mode or non-tmpfs
mounts before lease claim. The source-independent synthetic host reporter
and final verifier require matching positive mount evidence.

This repairs a staging capability boundary, **not** a new move, transport,
account, network, release or publisher authority.
